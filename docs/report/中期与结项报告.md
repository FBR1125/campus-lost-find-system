## 一、项目概述 【中期必填】
### 1. 项目背景
校园内师生丢失物品现象频繁，传统失物招领方式效率低、信息分散，不便师生使用。本项目为信息系统实践课程作业，面向校园场景，旨在搭建一个集中化的线上失物招领平台，解决校园内物品遗失信息分散、对接效率低的痛点，采用java、spring boot、MyBatis-Plus、vue3、mysql、Element Plus等技术开发，同时提升小组协作与开发能力。
2. 系统目标
1.核心功能目标：实现失物登记、招领发布、信息检索、认领审核等核心功能，满足全校师生（普通用户）与系统管理员的使用需求；
2.性能与适配目标：保证系统稳定流畅运行，适配校园常用的电脑、手机设备及主流浏览器；
3.课程考核目标：4 月 24 日前完成项目计划书汇报，5 月 13 日前完成系统开发与结题汇报，顺利通过课程考核。
### 3. 开发环境
· 开发工具：VS Code、IntelliJ IDEA、Dbeaver、Git；
· 数据库：MySQL 8.0；
· 运行环境：主流浏览器（Chrome、Firefox、Edge 等）、Windows/Linux 操作系统。

## 二、需求分析 【中期必填】
### 1. 功能需求
1）用户分类及核心功能
普通用户：支持注册 / 登录、失物登记（填写遗失物品信息）、招领发布（发布拾获物品信息）、信息检索（按条件查找失物 / 招领信息）、认领申请（对招领信息提交认领申请）、个人中心（查看 / 管理个人发布 / 申请记录）；
管理员：支持登录、信息审核（审核用户提交的失物 / 招领信息）、用户管理（查看 / 管理用户账号信息）、系统管理（基础配置、日志查看等）；
公共功能：首页展示（失物 / 招领信息推荐）、分类导航（按物品类型 / 发布时间等分类）、密码找回（通过安全验证找回账号密码）。
（2）核心业务流程
失物登记流程：用户登录→填写失物信息（物品名称、类型、遗失地点 / 时间、特征等）→提交审核→管理员审核通过后展示在平台；
招领发布流程：用户登录→填写招领信息（物品名称、类型、拾获地点 / 时间、特征等）→提交审核→管理员审核通过后展示在平台；
认领申请流程：用户检索到招领信息→提交认领申请（填写认领依据）→管理员审核→审核通过后通知双方对接认领。
### 2. 非功能需求
性能要求：页面加载时间≤3 秒，接口响应时间≤1 秒，系统支持至少 50 人同时在线操作；
安全要求：用户密码采用 MD5 加密存储，系统实现权限分级（普通用户 / 管理员），拦截违规信息提交；
兼容性要求：适配 Chrome、Firefox、Edge 等主流浏览器，兼容电脑（Windows/Linux）等终端设备的显示与操作。

## 三、系统设计 【中期必填】
### 1. 系统架构
本系统采用 B/S（浏览器 / 服务器）架构，整体分为三层架构设计：
表现层（用户交互层）：基于 Vue3+Element Plus 实现，负责用户界面展示、交互操作接收与反馈，适配多终端设备的页面渲染；
业务逻辑层（核心处理层）：基于 Java+Spring Boot 实现，负责接收表现层请求，处理失物登记、招领发布、审核、认领等核心业务逻辑，实现权限校验、数据校验等功能；
数据访问层（数据库交互层）：基于 MyBatis-Plus 实现，负责业务逻辑层与数据库的交互，完成数据的增删改查操作，保证数据一致性。
### 2. 模块设计

## 四、系统实现 【中期部分填写；结项补全】
### 1. 关键技术
（1）核心框架与工具
前端：Vue3（组合式 API 实现组件化开发）、Element Plus（快速搭建适配多终端的 UI 界面）、Axios（实现前后端接口请求）；
后端：Spring Boot（快速构建后端服务，自动配置核心组件）、MyBatis-Plus（简化数据库 CRUD 操作，支持分页、条件查询等）；
数据库：MySQL 8.0（关系型数据库，保证数据存储的一致性与完整性）；
其他：MD5 加密（用户密码加密）、Git（版本控制与小组协作）。
（2）技术难点及解决方案
难点 1：前后端数据交互的一致性与安全性解决方案：后端接口统一返回格式（状态码、消息、数据），前端统一拦截处理；接口请求添加参数校验，后端对敏感操作（如审核、认领）增加权限校验。
难点 2：多终端页面适配解决方案：采用 Element Plus 的响应式布局组件，结合 CSS 媒体查询，针对电脑、手机等终端调整页面布局与组件尺寸。
难点 3：数据关联查询（如用户 - 招领信息 - 认领记录）解决方案：基于 MyBatis-Plus 的关联查询功能，设计合理的外键关系，通过 Lambda 表达式简化多表联查逻辑。

3. 问题与改进
（1）测试发现的主要问题
账号注册环节存在用户ID无长度限制问题，输入过长账号ID时，会出现数据适配异常，不符合系统账号注册规范。
（2）对应改进措施
针对上述问题，对系统注册功能进行专项优化，新增用户ID长度限制校验机制。前端增加输入长度实时校验，后端同步匹配长度校验规则，当用户输入过长账号ID时，系统自动拦截提交操作并给出合法提示，规范用户注册输入格式，解决账号ID长度异常问题，目前该问题已完全修复，注册功能运行正常。

六、用户手册
1. 环境配置要求
本系统仅支持电脑端部署与使用，所有运行、操作、测试流程均基于电脑设备完成，无需移动端设备适配，具体软硬件环境配置要求如下：
（1）硬件环境
操作系统为 Windows 10 及以上版本电脑，基础配置 CPU i5、8G 及以上运行内存，保证系统服务稳定运行、页面操作流畅无卡顿。
（2）软件环境
- 运行浏览器：主流电脑端浏览器，Chrome、Edge 最新稳定版本
- 运行依赖：JDK 21 版本、MySQL 8.0 数据库
- 开发部署工具：IntelliJ IDEA、DBeaver 数据库管理工具
2. 部署步骤
本系统采用前后端整合部署方式，仅针对电脑端环境部署，具体部署流程如下：
（1）数据库部署
打开 DBeaver 数据库工具，连接本地 MySQL 8.0 服务，手动创建数据库，数据库命名为 campus_lost_find，字符集设置为 utf8mb4，排序规则统一配置为通用规则。执行项目内提供的建表 SQL 语句与初始化数据 SQL，自动生成系统所需数据表与基础数据，完成数据库初始化配置。
（2）后端项目部署
将项目完整源码导入 IntelliJ IDEA 开发工具，配置项目 JDK 版本为 JDK 21，等待 Maven 依赖自动加载完成。打开项目配置文件 application.properties，修改数据库连接地址、用户名、密码为本地 MySQL 对应配置信息，保证数据库连接参数与本地环境一致。配置完成后，启动系统主启动类，等待项目运行启动成功，后端服务正常监听端口。
（3）前端页面部署
将项目 frontend 文件夹内所有前端静态页面文件，复制放置到项目 resources 目录下的 static 文件夹中，实现前后端资源整合，由 Spring Boot 统一托管静态页面，无需单独配置前端服务。
3. 访问方式
本系统仅支持电脑端浏览器访问，项目启动成功后，打开电脑端 Chrome 或 Edge 浏览器，在地址栏输入本地访问地址即可进入系统。
